### 三个关键设计（都踩过坑才定下来的）
1. **`fs.copyFileSync` 不能用来备份这个库**：库跑 WAL，实测 `app.db-wal` 3.5 MB 而主文件停在一周前 ——

   测试里复制靶库同理。
2. **演练模式不用复制一份逻辑**：整轮包在 `SAVEPOINT article_dedup` 里，dryRun 时 `ROLLBACK TO` 而不是
   `RELEASE` —— 走的是**同一段代码**，所以演练数字就是真实执行的数字，不会两套逻辑漂移。
3. **`user_words` 有 `UNIQUE(user_id, word, article_id, sentence)`**，迁移必然可能撞键。
   撞键走「合并」：**先 `DELETE` loser，再 `UPDATE` winner** —— 顺序反了会在 winner 是「源行」时
   把它改挂到保留文章、与尚未删除的孪生行直接撞唯一键。
   **这个 bug 真实数据没暴露**（那次 winner 恰好是孪生行），是自造样本的 `qa_dup_*` 用例逼出来的。

- 标题只做轻归一化（空白 / 引号 / 大小写），**绝不做前缀或模糊匹配**：

- 新增 CLI `backfill_user_word_definitions.js`（默认演练，`--apply` 才写，写前 `db.backup()`）。
  npm：`backfill:userwords` / `backfill:userwords:apply`。
- **真库执行结果**：34 条收藏，24 条字面量「暂无释义」→ 全部由**词典层**补上真释义
  （语境库命中 0 条 —— 因为词典优先，命中了就不会再问语境库），占位归零；收藏行数未变。

  样例：`last → adj. 最后的, 末尾的, 最近的`、`literature → n. 文学, 文艺, 著作`。

**踩到的定义陷阱（值得记住）**：`''`（空串）是「两层都查不到」的**终态**，但它同时也是
`isRealUserWordDefinition` 眼中的「非真释义」→ 下一次运行它**仍是 candidate**。
所以幂等不能断言 `candidates === 0`，只能断言 **`changed === 0`**（值没变就跳过写入）。
report 里专门加了 `alreadyEmpty` 字段把这两种情况分开报。

### 点 2：句子翻译失败不再静默降级
原来 `queue.js` 的两行（`sentences = sentenceFailed ? [] : ...` / `updateArticleQuestions`）
把「翻译失败」写成了 `status='completed'` + `sentences=[]` —— 用户只看到「这篇没译文」，
根本不知道是**失败**。

改动（**三态 → 四态**，`articles.status` 多了 `partial`）：
- `db.js`：新列 `articles.sentences_error TEXT`（可空列 + `migrateArticleErrorSchema()`，
  沿用「ADD COLUMN 只接受常量默认值 + 吞 duplicate column 竞态」的老套路）；
  `updateArticleQuestions(id, q, s, {status, sentencesError})` —— **默认仍是 completed**，
  老调用方行为不变。
- `queue.js`：句子 promise 的 catch 里写 `sentencesFailed/sentencesError` 进内存任务表；
  `Promise.allSettled` 之后取 `sentencesErrorMessage`；落库时
  `status = sentenceFailed ? 'partial' : 'completed'`；`processWithRetry` 用 `console.warn`
  打「部分完成」而不是 `console.log` 的「完成」。
- `server.js`：`/api/article-status/:id` **必须**加 `partial` 分支 —— 否则会落进下面的
  pending/processing 分支，前端以为还在跑、一路轮询到 5 分钟超时，永远进不了阅读页
  （把一个静默降级换成了更糟的「卡住」）。另在 `/api/article/:id`、`/api/articles` 透出 `sentencesError`。
- `app.js`：`pollArticleProgress` 加 `partial` 分支（回填 + 提示 + 进阅读页）；
  新增 `showSentenceFailedNotice/syncSentenceFailedNotice`；`renderArticle` 每次切文章重判提示条
  并收起上篇残留的 `#fallbackNotice`；`mapServerArticle`/`loadArticleDetail` 透传 `sentencesError`。
- `index.html`：新增 `#sentenceFailNotice` 提示条（与整篇降级的 `#fallbackNotice` 分开，避免语义混淆）；
  指纹 `app.js?v=20261006_2` → `20261006_3`。

**为什么不用 `failed`**：前端 `failed` 会弹「AI 服务暂时不可用，已切换到基础模式」的整篇降级提示，
而 partial 的题目/释义都是**真结果**，只是译文缺失 —— 混在一起会误导用户。
