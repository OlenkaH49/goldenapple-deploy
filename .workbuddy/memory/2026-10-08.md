# 任务二（同日续）：题目生成 0 题 + 拖拽收藏失效 → 原来是同一条因果链

用户报两个问题，排查后确认**是同一个根因的两次显形**。

## 症状
1. 日志「quiz_generator 返回 0 题 → 无可用题目，使用降级题目」。
2. 「这次改完，拖拽收藏失效了」——用户猜是猜词模式覆盖了拖拽事件。

## 根因（连环，一层套一层）
```
coze.js generateQuestionsWithCoze: JSON.parse 失败 → 只 console.warn → data=null
  → rawQuestions=[] → 返回 { questions: [], success: true }   ← 「空成功」，与句子翻译那次一模一样
  → queue.js 静默落 generateFallbackQuestions 的降级题
     （fallback.js 打 isFallback:true + answerMode:'selection'）
  → app.js applyQuizState 看到这些标记 → fallbackQuizActive = true（「降级划选答题模式」）
  → app.js onSpanPointerDown 开头写死 `if (fallbackQuizActive) return;`
  ⇒ 正文单词**一按就 return**，拖拽收藏全废。
```
**所以「拖拽坏了」和「题目没了」是同一件事。** 用户给的方向（dragstart / 猜词模式）全是冤枉的：
本项目拖拽走 **pointer events**，`dragstart` 根本没绑定；猜词模式也没碰拖拽。

## 怎么找到的（可复用）
- 真浏览器里**包裹函数数调用次数**是定位「交互没反应」最快的办法：
  `w('onSpanPointerDown','pd'); w('onSpanPointerMove','pm');`
  → 结果 `pd:1, pm:0` ⇒ 入口被守卫提前 return 了 ⇒ 去读那个函数开头的 early return。
  （这一步把「猜测」直接变成「证据」。）
- `fallbackQuizActive` 的真实赋值点在 `app.js:3088` 附近（按题目 `isFallback/answerMode` 判）。
- 验证持久：`SELECT COUNT(*) FROM articles WHERE source='upload' AND questions LIKE '%isFallback%'` → 3 篇。

## 修法
- `coze.js`：抽 `runQuizOnce(cfg, ...)` 单模型函数 —— **完整打印原始返回**（用户明确要求，前 4000 字 +
  总长）、解析失败/缺 `questions`/空数组/题干全空 → **全部抛错**；
  `generateQuestionsWithCoze` 改为走既有 **`runWithModelFallback`（GLM→DeepSeek）**。这才是「AI 没返回」的兜底。
  兼容：响应若是纯数组仍按题目列表接受。
- `queue.js`：降级题日志补上**真实原因** + 明确写出「会进入降级划选模式 → 禁用正文拖拽」这条因果连线。

  普通模式越过 5px 就建（行为不变），降级模式**只有拖到收集区附近才建**，于是「划选作答」与「拖拽收藏」共存；
  `wasDragging` 判据从 `moved` 改成 `!!ghost`。② 拖拽全链路加日志（起手/阈值/命中区/落点/结果）。
  ③ **顺手修一个真 bug**：拖到收集区松手时 pointerdown/up 的 target 不同 → click 派发到 readContent 之外 →
  `spanJustDragged` 永远没被消费 → 下一次正常点词被吞掉（表现：拖过一次后点词不弹卡）。
  改在 `onSpanPointerDown` 开头复位该标记。

## 收藏释义优先级：本句语境释义 → 文章词表 → 词典层首义（请求五，已落地 + 已测）

用户诉求：part-time 词典无「兼职的」（靠「联网深查」补的），但收藏下来的是词典的 part 释义。

1. `getWordContext`（L2）要求 `word + context` **逐字符相等** → 正文 DOM 句子与写库句子常因空格/标点/站标 `[xxx]` 不同而 miss
