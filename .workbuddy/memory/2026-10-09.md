**旧实现**：`renderSummary()` 里
`'<div class="word-tag">' + word + ' · ' + meaning + '</div>'` ——

所有词连成一行 `determines · 决定；确定（determine 的第三人称单数） possibilities · 可能性（复数）`，糊成一片。

**新实现**：
- `app.js` 新增纯函数 **`splitMeaningNote(meaning)`** → `{ main, note }`

    <div class="sw-head"><span class="sw-word">determines</span><span class="sw-idx">1</span></div>
    <div class="sw-meaning">决定；确定</div>

  否则 flex/grid 同优先级靠顺序取胜，容易踩坑）；

## 刷新被打回欢迎页 + 返回键直接退出应用（10:00 起，已改 + 已测）

**用户报**：①刷新页面会直接返回到「登录页」（就是欢迎页 `#startingPage`），而不是停在原页面；
②按浏览器的返回键不是回到上一页，而是直接退出了这个软件。

### 根因

- **①**：`DOMContentLoaded` 里无条件 `showScreen('startingPage')`。**没有任何会话持久化**——
  刷新后 `let userData` 回到空对象，`getUsername()` 也就退化成 `golden-apple-user`，
  所有 `/api` 请求带着错的 `x-username`（这其实是个隐藏的串号 bug，只是用户先撞见的是「被登出」）。
- **②**：全项目**一处 `history.pushState` 都没有**（`grep -rn "history\." app.js` 为空）。
  SPA 切屏只改 class → 浏览器历史栈里永远只有「进站」那一条 → 一按返回就离开本站。

### 改法（全在 app.js，前端静态文件，不用重启服务）

新增一层 **「会话保持 + 浏览器历史」**（放在 `showScreen` 上方）：

- **会话**：`localStorage.gaSession = { started, screen, articleId, at }`。
  `showScreen()` 每次切屏 `patchSession({screen})`；阅读页额外记 `articleId`。
  `DOMContentLoaded` 里 `started` 为真 → `restoreUserIdentity()`（只恢复 userName/level/streak）
  → `restoreScreenFromSession()` 还原上次的屏 → **补调 `initBackendSync()`**
  （会话恢复不会走 `startApp()`，不补的话主界面没打卡、没收藏数据）。
- **历史**：`bootHistory(root)` 建根条目 **+ 再压一条同屏副本**（关键！见下），
  `showScreen` 非 popstate 触发时 push（带 `gaDepth`）。
  `popstate` → `navigateBackTo(target)` 在应用内回退（阅读页重绘、单词本重算，
  练习状态不在了就退回主界面）。
- **`pushedScreens` 数组**与 depth 对齐。目标屏**已经在栈里**（含根屏）→ `history.go(-N)` 真回退，
  **不再压新条目**；否则点应用内的「← 返回」会多出一条，用户再按浏览器返回键会「前进」回刚才那页。

### ★ 两个非直觉的坑（都踩过）

1. **必须多压一条「根屏副本」**。浏览器在**最根那条历史**上再按返回会直接离开本站，
   而且**根本不会触发 popstate** —— 留给我们的唯一机会是让用户退到根屏时还有一条可退。
   有了副本：退到根屏（正常切回去）→ 再按返回（被接住，只 toast「再按一次返回即可退出」）→
   再按才真正出栈。所以根屏守卫判的是「**当前已经在根屏**」而不是「退到深度 0」——
   判成后者的话，「从上传页退回主界面」会被误当成「已在根部」，主界面永远回不去。
2. **条目下标 ≠ depth**：条目 0/1 是根 + 根副本，depth d 对应条目下标 `d+1`，
   当前在 `pushedScreens.length + 1`。所以 `delta = pushedScreens.length - idx - 1`
   （写成 `length - idx` 会差一格，直接跳错屏）。
3. `bootHistory` 里必须**先 `historyBooted = true` 再 `syncHistoryEntry`**，
   否则 `syncHistoryEntry` 自己的闸门判断会把根条目吞掉（测试 B1 冒烟抓到的）。

### 「开始旅程」用 replace 而不是 push

`startApp()` 里把 `startingPage` 那条历史**就地改写成 `dashboardPage`**（`showScreen(id,{replace:true})`）。
否则返回键会再看到一次欢迎页 —— 在用户眼里就是「被登出」。

## 路由被劫持：「一进网页直接是阅读页」（13:41 起，已改 + 已测）

**用户报**：改了部署配置后「一进网页，直接是文章阅读页」，欢迎页与 Dashboard 全被跳过；

### 根因（不在服务端，也不在「部署配置」）

`server.js` 的 `GET /` 只 `res.sendFile('index.html')`，**没有任何重定向**；`index.html` 里
`startingPage` 本来就是 `class="screen active"`。问题 100% 在前端：

**老版本把会话写进了 `localStorage.gaSession`（永久 + 跨标签）**。只要用户曾经点进过阅读页，
之后**每一次进网页**（新标签 / 重开浏览器 / 直接输网址 / 隔天再访问）都会被那条旧会话劫持 →
`DOMContentLoaded` 里 `restoreScreenFromSession()` 直接 `openArticle()`，欢迎页和 Dashboard 全跳过。
用户排查方向里的「是不是 localStorage 里有已登录状态」——**答对了，就是它**。

### 改法（app.js / index.html，都不用重启服务）

1. **会话介质 `localStorage` → `sessionStorage`（标签页级）**，新增 `sessionStore()` 统一取。

   - 取不到 sessionStorage 时返回 `null` → 退化为「不做会话保持」，**绝不回退 localStorage**。
2. **启动清理遗留的 `localStorage.gaSession`** → 用户不用手动清缓存，下次刷新即恢复正常流程。
3. **`?fresh=1` / `#fresh` 兜底开关**（`wantsFreshStart()`）→ 强制丢弃会话回欢迎页，排查用。
4. **路由日志**：`DOMContentLoaded` 打 `🧭 [路由] ===== 启动路由决策 =====`（会话介质 / 会话内容 / 判定），
   `showScreen` 每跳打 `🧭 [路由] A → B（历史回退/replace 标注）`。
5. ★ **两个「顺手修」的连带 bug**（不修会在首访回欢迎页后爆数据问题）：
   - `restoreUserIdentity()` 改为**无条件调用**。原来只在 `started` 为真时调，首访时 `userData.userName` 为空 →
     `getUsername()` 退化成 `golden-apple-user` → 欢迎页拉文章 + 之后所有 `/api` 都带错 `x-username` → 拉到别人的收藏。
   - `startApp()` 里会 `localStorage.removeItem('gaUserData')`，**必须先把 `prevUserName` 快照下来**，
     输入框为空时用它兜底 → 否则首访点 Start Journey 直接丢身份。
